# lens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tmux panel that shows every edit Claude Code makes, live, navigable with vim motions, so the user can read and learn from the code.

**Architecture:** One Go binary. A `PostToolUse` hook appends each edit to an append-only JSONL log under `$XDG_STATE_HOME/lens/<session_id>/`, spawning a tmux pane running the TUI on the first edit. The TUI tails that log. Claude Code's own `structuredPatch` and `originalFile` supply the diff and its context, so nothing is snapshotted or re-diffed.

**Tech Stack:** Go 1.22+, Bubble Tea, Lipgloss, Chroma. No shell or `jq` dependency.

**Spec:** `docs/superpowers/specs/2026-09-18-lens-design.md`

## Global Constraints

- Module path `github.com/mahmood/lens`; binary installs to `~/.local/bin/lens`.
- **Hooks always exit 0.** A capture failure must never disrupt a Claude session.
- Hooks do bounded work only: parse, append, return. Never block on the TUI.
- Unparseable or unrecognized payloads append to `$XDG_STATE_HOME/lens/debug.log` rather than failing.
- Context windows are capped at 50 lines either side of a hunk. Full file contents are never written to disk.
- Storage is per-session and ephemeral: deleted on TUI quit, swept after 24h.
- Fixtures in `internal/capture/testdata/probe-payloads.jsonl` are real captured payloads. Tests parse them; they are not hand-written approximations.
